# 企业版（需求 + 出图）

叠加在 `product-requirements.md` 与 `ui-preview.md` 上，不替代它们。

适用于：蓝图 `headless-workspace`，或描述含「企业 / 后台 / 管理端 / B2B / 工作台 / 运营 / 审批 / 权限 / 租户」。C 端营销站、文档站、组件库不要用本文。

本轮默认做 **可演示的企业工作台 MVP**，不是完整 IAM / 中台。

## 需求增补

`docs/requirements.md` 在通用六章之外，必须再写：

1. **角色**：至少 2 个（如管理员 / 操作员）。写清「能看见什么 / 不能做什么」。未提 SSO、AD、细粒度 ACL 时，用角色枚举 Mock，不要设计完整权限模型。
2. **主导航**：侧栏分组（工作台 / 业务列表 / 详情或抽屉 / 设置）。设置里只放本轮用得到的项。
3. **列表页契约**：筛选、搜索、分页或「加载更多」、行操作、空表。P0 至少一张主列表能走通「筛选 → 打开详情」。
4. **详情**：独立页或抽屉；只读字段与 1 个主操作（保存 / 提交 / 启用）。
5. **企业态**：无权限、无数据、加载骨架、提交失败（可重试）。无权限不要用空白页，要说明原因和返回。
6. **P0 边界**：登录可用占位（本地开关或写死当前角色）；不要把多租户切换、审计日志、审批流、导入导出做成 P0，除非用户点名。

### 企业版 P0 验收模板（按描述裁剪，不要全抄）

- [ ] 能以某个角色进入工作台，看到侧栏与当前角色
- [ ] 主列表有数据、空态、筛选各一态
- [ ] 能打开一条详情并完成一个主操作
- [ ] 无权限角色能看到拦截说明
- [ ] `packages/engine` 有角色与列表状态；页面在 `apps/web/src/pages`

## 出图增补

三套必须都是 **同一套企业 IA**（侧栏 + 顶栏 + 主列表），只改密度与视觉，禁止一套改成营销首页。

| 套 | 名称 | 密度 | 主界面 |
|----|------|------|--------|
| A | 控制台 | 高 | 左导航 + 顶栏（租户/角色占位）+ 数据表 + 行内操作。适合运营每天盯表。 |
| B | 工作台 | 中 | 左导航 + 概览卡片 + 待办/最近记录，主列表放第二屏或下半。适合管理者进门。 |
| C | 紧凑操作台 | 高 | 左树或二级导航 + 右表 + 右侧详情抽屉。适合改一条记录就走。 |

每套额外给一张 **无权限或空表** 预览，文案与需求文档一致。

### 企业视觉约束

- 顶栏稳定：产品名、当前工作区或租户占位、当前角色、主按钮不超过 1 个
- 表格列要对齐、表头固定；不要用卡片冒充「企业风」却看不出列
- 主色用于按钮、当前导航、状态点；不要大面积渐变
- 状态色：成功 / 警告 / 危险 / 中性，预览里至少出现两种
- 不要仪表盘堆满假图表；最多一个概览数字条，主体仍是 P0 任务

### 选定后

在 `docs/requirements.md` 写明：选定套（A/B/C）、主列表页路径、详情形态（页/抽屉）、当前 Mock 角色。然后再问是否写代码。

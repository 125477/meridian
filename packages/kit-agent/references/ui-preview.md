# UI 预览图

仅在 `docs/requirements.md` 已获用户确认之后使用。三套预览必须**同一信息架构、同一主流程**，只改视觉与密度，方便对比。

企业后台 / B2B / 工作台：叠加 `enterprise.md` 的出图约束。

## 目标

在 `<project>/design-previews/` 给出 2–3 套**主界面**预览（不是营销落地页），先图后文，让用户选一套再写代码。

每套一个子目录：`A/`、`B/`、`C/`。至少包含：

- 主界面（登录后第一屏或 P0 任务所在页）
- 一种关键状态（空态或错误，三套不要重复同一种）
- `README.md`：风格名、适用场景、色/字/密度、与需求章节的对应

## 出图方式（按可用性降级）

1. **本机有 `ui-ux-pro-max` Skill**（`$HOME/.cursor/skills/ui-ux-pro-max` 等）：可用来检索风格 / 色板 / 字号建议，再生成预览。不是硬依赖。
2. **能生成图片**：按已确认需求出主界面预览图，写入对应子目录。
3. **都不能**：用 HTML 或 Markdown 线框还原主界面（顶栏、侧栏、主列、表格/卡片、主按钮），并附 token 表（背景 / 文本 / 边框 / 主色 / 字号 / 间距）。禁止只丢一段色板或形容词让用户选风格。

## 硬规则

- 禁止未确认需求就出图
- 禁止三套只是换主色
- 禁止用 emoji 当图标；标注「图标位」即可
- 预览里的文案必须来自需求文档，不要发明新导航
- 选中一套后，把选择写入 `docs/requirements.md` 末尾「选定 UI」，再问是否写代码

## 通用三套（非企业产品可用）

| 套 | 密度 | 气质 |
|----|------|------|
| A | 中 | 中性工作界面，白底、少装饰 |
| B | 低 | 更宽松，卡片为主，适合浏览 |
| C | 高 | 深色或高对比，适合长时间操作 |

用户指定风格时，用指定风格替换其中一套，仍保持同一 IA。
